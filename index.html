Executive Briefing & Presentation

Bypassing the Perimeter: The Kerberoasting Threat

Active Directory Cryptographic Vulnerability Analysis
Bypassing-the-Perimeter.pdf (Executive Briefing)
SLIDE 1: THE HOOK Theme: Trusting the Courier

Traditional Perimeter Defense vs. Cryptographic Cargo

The core structural vulnerability of enterprise identity does not lie at the perimeter gate, but in the cryptographic design of internal authentication. Under the Kerberos protocol, the Key Distribution Center (KDC) is structurally obligated to hand over an encrypted Service Ticket (TGS) to any authenticated domain user who requests it.

Traditional Perimeter Defense Cost: $2M+

Focuses heavily on external traffic filtration. Completely blind to internal protocol service ticket requests.

Cryptographic Identity Cargo Cost: Low

Focuses on key strength. Weak legacy service account passwords compromise the entire internal identity trust chain.

SLIDE 2: THE EXPLOIT Theme: Silent Passage Out of the Vault

How Kerberoasting Bypasses EDR & Layer-7 Firewalls

Because Kerberoasting utilizes completely legitimate authentication requests, standard security controls fail to flag it. An attacker only needs low-level domain access to query Active Directory for accounts with registered Service Principal Names (SPNs).

1. Low-Level Account

Compromised user account (e.g. shipping clerk)

2. KDC (Domain Controller)

Processes valid TGS-REQ query

3. Encrypted TGS Ticket

Issued silently without lockout triggers

4. Local Memory Extraction

Saved to disk for offline GPU cracking

SLIDE 3: SYSTEMIC FAULT Theme: Offline GPU Force Crack

Offline Password Cracking & Lockout Blindspots

Once the encrypted TGS ticket is saved locally, attackers use GPU clusters to perform dictionary and wordlist attacks against the legacy RC4/NTLM hashes. Because this occurs completely offline, Active Directory account lockout policies are entirely unaware.

Attack Vector Parameter Risk Impact
Extracted NTLM Hash Static Input File
GPU Cracking Speed Billions of guesses / sec
AD Domain Controller Lockout Bypassed (Zero AD interaction)
SLIDE 4: ARCHITECTURAL FIX Theme: gMSA Upgrade

Group Managed Service Accounts (gMSAs) Neutralization

The permanent remediation is migrating legacy service accounts to Active Directory Managed gMSAs. This offloads credential management to AD, enforcing 128-character machine keys, mandatory AES-256 encryption, and automated 30-day credential rotation with zero human intervention.

Legacy Service Account

  • • Human-generated weak passwords
  • • Vulnerable to RC4 cipher degradation
  • • Manual updates risk system downtime

gMSA Upgrade Architecture

  • • 128-character complex machine keys
  • • Enforced AES-256 encryption
  • • Automated 30-day password rotation
SLIDE 5: EXECUTIVE DECISION Theme: Risk vs Business Value

Executive Call to Action: Compliance & Uptime

Maintaining legacy service accounts to preserve uptime is a false economy. Leaving static administrative passwords unrotated violates SOC 2 Criteria CC6.3 and NIST SP 800-53 (IA-5). A planned 4-hour maintenance window permanently protects enterprise assets from multi-million dollar ransomware exposure.

Option A: Do Nothing $56M Est. Risk Exposure Post-incident forensic audit will flag executive negligence.
Option B: Execute gMSA Migration 4-Hour Maintenance Window Achieves full compliance validation & neutralizes Kerberoasting.

Compliance & Security Playbook

OWASP Top 10 (2026) Mitigation Controls

Source: OWASP_2026_Mitigation_Plan.docx
A01:2026 - BROKEN ACCESS CONTROL #1 Top Risk

API Endpoint Ownership Validation

Every API endpoint must verify ownership server-side. Never rely on client-side ID parameters alone.

SELECT * FROM tickets WHERE id = ? AND user_id = current_session_user;
Verification: Expect HTTP 403 Forbidden for un-owned resource queries.
A02:2026 - CRYPTOGRAPHIC FAILURES Data Protection

TLS 1.3 & Key Vault Encryption

Disk encryption enabled for managed databases (RDS/Cloud SQL). Secrets stored strictly in AWS Secrets Manager or Vault.

Strict: Enforce TLS 1.3 only | Disable legacy SSL/TLS 1.0/1.1
Ops Execution: Zero hardcoded secrets in versioned .env files.
A03:2026 - INJECTION (SQL / NoSQL / COMMAND) Query Defense

Parameterized Queries & WAF Filtering

Mandatory use of parameterized queries to prevent string concatenation attacks. Database users configured with Least Privilege.

Deploy Web Application Firewall (WAF) SQLi Protection Rule Set
A04:2026 - INSECURE DESIGN Business Logic

Centralized Server Financial Calculations

"Never trust data from the client." The client sends intent (Item ID); the server determines fact (Price & Taxes).

Prevents "Zero Naira / Zero Dollar" price manipulation exploits
A05:2026 - SECURITY MISCONFIGURATION IaC Automation

Infrastructure as Code (Terraform)

Automated provisioning ensures no public S3 buckets or leftover debug modes. Nmap scans enforce minimal exposed ports (80/443).

A06:2026 - VULNERABLE COMPONENTS Supply Chain

Automated CI/CD Vulnerability Scanning

Integration of Trivy / Snyk into GitHub Actions. Pipeline automatically breaks builds if Critical CVEs are detected.

Additional Controls: A07 - A10 Execution Matrix

A07 Auth Failures MFA for admin accounts + 5 attempt/min IP rate limiting.
A08 Data Integrity CI/CD is the single source of truth. Checksum verification.
A09 Logging Failures Centralized CloudWatch/ELK + automated 403 anomaly alerts.
A10 SSRF Defense Network egress filtering. Web server only reaches DB & payment gateway.
